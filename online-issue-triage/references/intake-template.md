# 排查信息收敛

信息不足时，优先补能够决定下一步路由与范围的信息，一次通常只问一到三个关键问题。已经确认的信息不重复问。

## 通用信息

1. 是测试还是生产？对应哪个部署区和服务？
2. 当前最可靠的关联 ID 是什么：trace、请求、任务、对象或流程实例？
3. 大致时间窗口、用户看到的现象和预期分别是什么？

只有部署区仍不足以选择 SLS 路由或数据库实例时，再请用户提供服务、项目索引或本机配置中的准确实例名称。不要维护“某业务总在某实例”的公共硬编码对照。

## 按现象补充

- 技术异常：优先取 trace、错误原文和关键栈帧；已给 trace 时仍需确认环境。
- 对象未导入：区分完全不存在、已存在但状态异常，以及页面筛选不可见；确认对象 ID 与明文/哈希的口径。
- 流程不推进：区分未生成实例、等待节点、执行失败或等待重试；确认最后一次正常推进的时间。
- 页面或接口异常：确认具体用户路径、调用入口、权限与租户范围。

## 提问边界

只问会影响结论或操作范围的未知项。实例、表结构、调用链等可查证事实先用已授权只读入口查证；没有权限或条件时说明缺口，不让用户猜技术事实。

不因为只有一个对象就默认查询范围足够安全，也不在项目和实例尚未明确时扩大扫描。
