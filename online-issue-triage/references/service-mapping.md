# 服务与代码定位

本文件不维护实际组织的服务清单或本地代码目录。服务名、部署区和仓库映射由本机配置、项目索引、日志和实际部署信息确认。

## 定位顺序

1. 从用户请求和环境证据确认服务名及部署区。
2. 从项目索引、构建文件或部署配置定位目标仓库。
3. 加载目标仓库与目录的协作规则。
4. 在已确认的仓库内按类名、方法名、异常或请求路径检索。

以下是虚构示例，不能直接作为目标环境的路由：

```bash
rg -n "example-api|example-worker" <已确认仓库>
rg -n "ExampleHandler|ExampleException" <已确认模块>
```

已经拿到栈帧或请求路径时，优先搜索精确符号，不先递归扫描整个 `WORK_ROOT`。限定范围找不到后再按调用链逐步扩大。

## 结果边界

- 日志中的服务名不一定等于本地目录名。
- 业务调用关系不等于构建产物依赖关系。
- 国内、海外、测试和生产的路由分别确认，不根据名称猜部署位置。
- 没有映射或访问权限时报告缺少的线索，不借用其他环境的代码或数据作为当前证据。
