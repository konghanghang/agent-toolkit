# 提交消息与 Shell 引用

沿用项目语言、格式、scope 和必要模板；没有明确要求时参考少量近期标题，不读取整段历史。无提交历史时只依据项目规范及本次内容。

## 消息长度

- 标题简短，只描述实际改动，不写背景、评价或句号。简单改动默认只用一行。
- 标题不能充分说明关键规则、兼容性、默认值、迁移或取舍时才补正文；项目明确要求正文时遵守。
- 正文与标题之间留一个空行。两项及以上独立内容逐行以 `- ` 开头；单一原因可用短段落。不机械罗列文件、验证流水或重复标题。
- 用真实换行，不把字面量 `\n`、`\r\n` 当换行写入消息。

简单的无签名提交示例（签名取决于预检，不因示例改变）：

```bash
git commit -m 'docs: 更新配置说明'
```

## 多行消息

直接使用两个 `-m` 参数，不创建临时消息文件，不使用 `-F`。正文整体作为一个参数；Bash／Zsh 用反斜杠续行，PowerShell 用行尾反引号。单引号内部需要单引号时按当前 Shell 正确转义，不把 `JSON.stringify()` 当作 Shell 转义。

Bash／Zsh：

```bash
git commit -S \
  -m 'feat(api): 支持本地获取 OpenAPI AccessToken' \
  -m '- 新增本地 AccessToken 接口，转发 cropId 和认证请求头到 SaaS
- 保留上游响应状态、响应体及 X-Trace-Id
- 保持现有业务鉴权行为不变'
```

PowerShell：

```powershell
git commit -S `
  -m 'feat(api): 支持本地获取 OpenAPI AccessToken' `
  -m '- 新增本地 AccessToken 接口，转发 cropId 和认证请求头到 SaaS
- 保留上游响应状态、响应体及 X-Trace-Id
- 保持现有业务鉴权行为不变'
```

这些例子是独立提交调用，不与其他检查或写操作拼接。提交后核对完整消息；发现格式错误如实报告，不在缺少授权时 amend。
