# 排查提问模板

## 总原则

信息不足时，先补 **路由信息** 和 **主键 ID**，不要直接开查。

提问顺序：

1. 先确认要查国内 / 国内新业务 / 海外 / ai-open-api
2. 再确认关键 ID
3. 最后补时间窗口和现象描述

提问要求：

- 一次优先只问 1 到 3 个问题
- 问能直接决定下一步工具和路由的问题
- 不要把“可能有用”的所有问题一股脑全问出来

## 通用先问

当信息明显不够时，优先从下面挑：

1. 这是国内、海外，还是 `ai-open-api` 相关的问题？
2. 你手里现在最确定的 ID 是什么？
   - `traceId` / `taskId` / `flowDataId` / `requestId` / `smsId` / `号码`
3. 大概发生在什么时间？
   - 精确时间
   - 还是“今天 / 刚刚 / 某一批任务”

## 场景 1：技术 Trace 排查

### 已经给了 traceId

如果只给 traceId，优先问：

1. 这是国内、海外，还是 `ai-open-api` 的请求？
2. 如果不确定，报错大概来自哪个服务？
   - 例如：`data-center`、`sms-server`、`call-task`、`ai-flow-server`
3. 大概发生在什么时间？

### 没给 traceId，只给错误描述

优先问：

1. 有没有 `traceId` / `requestId` / 报错接口路径？
2. 这是哪个服务或哪个页面触发的？
3. 是国内还是海外？

## 场景 2：号码为什么没导入任务

优先问：

1. 你给的“任务 ID”具体是哪种 ID？
   - `taskId`
   - `flowDataId`
   - `requestId`
   - 不确定
2. 号码是明文手机号、`numberId`，还是已经 MD5 过？
3. 这是国内传统业务、国内新业务（短信/短链/WA/回调/AgentCC），还是海外？

补充问题按需再问：

4. 现象是“完全查不到号码”，还是“任务里有，但状态不对”？
5. 大概导入时间是什么时候？

## 场景 3：号码在智能任务为什么没流转

优先问：

1. 这是哪个任务的号码？
   - `taskId` / `flowDataId` / `requestId`
2. 你说的“没流转”具体是：
   - 没生成流程实例
   - 生成了但卡在某个节点
   - 状态报错 / 一直等待
3. 这是国内还是海外？

补充问题按需再问：

4. 号码是明文、MD5，还是 `numberId`？
5. 最后一次看到它正常推进，大概是什么时间？

## 当 SLS project 无法判断时

必须立即追问，不要盲切：

1. 这是海外问题吗？
2. 如果不是海外，是 `ai-open-api` 相关吗？
3. 如果也不是，那我按国内其他服务查，可以吗？

## 当 Archery 实例无法判断时

必须立即追问，不要凭感觉选库：

1. 这是国内大部分传统业务吗？
   - 如果是，优先 `main-db`
2. 还是短信 / 短链 / WA / 回调 / AgentCC 这类新业务？
   - 如果是，优先 `polarDB-TiDB`
3. 还是海外业务？
   - 如果是，优先 `海外生产数据库`

## 推荐问法

### Trace 场景

- `这个 trace 是国内、海外，还是 ai-open-api 的请求？`
- `如果你不确定区域，能告诉我是哪个服务在报错吗？`

### 号码 + 任务 场景

- `你这里的任务 ID 是 taskId，还是 flowDataId / requestId？`
- `号码是明文手机号，还是已经做过 MD5？`
- `这笔业务属于国内传统业务、国内新业务，还是海外？`

### 智能任务流转场景

- `你说的没流转，是没生成 flow_data，还是 flow_data 有了但卡住？`
- `你手里现在有 taskId、flowDataId、requestId 里的哪个？`

## 不要这样问

- 不要上来把国内、海外、号码格式、任务类型、时间窗口、服务名、表名一次性全问完
- 不要在还没确认 SLS project / Archery 实例前就直接开查
- 不要因为只有一个号码就默认它一定在国内主库
