# URL 权限 SQL

产出一条针对已确认接口的 INSERT，附执行前后核对 SQL。复用会话里已确认的接口、菜单和批次；缺少会改变登记结果的信息时才询问，不要求用户重新提供已知字段。

## 核对登记对象

- 用户给 URL 时定位真实调用方及 Controller；用户给功能或分支时检查本次新增的外部入口。已有接口只加字段，不等于新增 URL；内部 Feign/RPC 接口不自动登记到外部权限表。
- HTTP 方法从 Controller 和调用方确认。`t_url.path` 以网关实际送入权限校验的路径为准，包含必要的服务前缀，去掉查询参数；不能机械复制 Controller 路径，也不能一律添加或删除服务名。动态路径须核对现有匹配规则，不擅自放宽成通配路径。
- `app_code` 必须从目标项目的应用定义取得，不预设某个数值对应某类系统。权限按钮标识不等于菜单名称或菜单 ID。
- 菜单用 `app_code + name + path` 唯一定位，保留真实大小写；不使用前端侧栏展示名猜数据库 `name`，不将路由完整路径当成数据库 `path`。不同环境动态取 ID，不复用测试 ID。
- `action_type`：1 读、2 写，按业务副作用判断；POST 查询可为读，触发回调、发送、补推等为写。`verify_required` 通常为 1；设为 0 或公共菜单 `menu_id=-1` 须有用户明确口径或现有权限契约依据，不能用来绕过缺失菜单或授权。

## 只读取证

需要当前菜单、表结构或重复记录时，测试库使用 `$verify-test-db` 的只读入口；生产查询按 `$archery-prod-query` 的边界执行。当前环境没有对应技能或无法访问时，依据代码和已确认输入生成草稿，并明确待核对项，不声称已查库。

- 先从目标环境确认权限库及表。模板使用 `t_menu`、`t_url` 表达一种登记结构，不能据此推断任意项目使用同样的库名、字段或枚举。
- 菜单查询限定系统、名称和路径；URL 查询限定 `app_code + path + method`，只取登记相关字段。不扫描租户或用户业务数据。
- 无菜单、多个菜单或已有冲突登记时说明实际问题；不新增猜测菜单，不自动覆盖旧 URL。单环境核对结果不能当成生产验证。

工作区证据入口由项目规则和实际调用链定位；进入目标仓库前先加载适用规则：

- 网关过滤器：确认送入鉴权服务的真实路径与 HTTP 方法。
- 权限匹配服务：确认精确路径、动态路径、前缀和缓存行为。
- 登记实体、Mapper 和表结构：确认字段、枚举、ID 分配及审计约束。

不在公共 Skill 维护组织内部的绝对源码路径或包名，不将虚构示例路径当作已验证入口。

## 生成 SQL

读取并实例化 [assets/register-url.sql](assets/register-url.sql)。模板中的参数不是 SQL 变量；文本值用 SQL 单引号转义，数值参数校验后替换，交付内容不得残留 `{{...}}`。

- 模板按已确认的菜单唯一时插入；同应用、路径、方法已存在时不重复插入。影响 0 行须核对菜单和已有记录，不能直接判成功，也不自动更新旧登记。
- 沿用人工登记的 `MAX(id)+1` 方式，提示串行执行；它不保证并发分配 ID 的安全。目标表已有其他 ID 规则时遵循真实结构，不新增锁表流程。
- `create_by=1`、其他审计字段默认值沿用用户提供的登记格式；用户指定创建人或目标表约束不同时按已核实口径调整。
- 已明确为公共 URL 时才将菜单查询替换为 `-1`，省略菜单前查，保留应用、路径、方法的重复检查。不要为一个接口同时生成带服务前缀和不带前缀的两条权限。
- 插入 t_url 不代表角色或按钮授权已完成。按实际功能注明后续授权及缓存生效验证；不凭本模板生成其他权限关系表的写入。

## 文档落点与交付

用户要求写上线文档时，读取小组知识库 `AGENTS.md` 和交付流程的上线清单章节，将完整 SQL 增量写入该知识库实际使用的批次上线清单（例如 `delivery/releases/YYYYMMDD.md`）。批次沿用用户当前口径；不要另建需求专属上线文件。

简要说明执行环境、执行时机、核对结果和授权事项，同步修正摘要中“无 SQL”等冲突描述。回退记录本次实际新增 ID，先撤授权，再确认引用后清理本次登记；不生成会删除原有记录的宽泛 DELETE。提测文档需要同步时只引用上线清单中的 SQL。

按仓库规则做文档校验，报告登记参数、证据范围、文件位置和执行状态。生成 SQL、执行 SQL、提交文档和发布是不同动作，本技能不执行数据库写入；用户另有写入请求时转入对应数据库技能的操作流程。
