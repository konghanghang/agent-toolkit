# Agent 分工

主 Agent 留在当前对话中，负责目标、用户取舍、授权、方案整合和最终交付。下表条件成立且宿主有可用角色时，应主动委派，不要求用户重复指定 Agent。角色定义提供职责，本文规定调用时机；不因存在多个角色就每次启动全套。

## 何时使用哪个角色

| 场景 | 应使用的角色 | 主 Agent 保留的职责 |
|---|---|---|
| 多个模块、服务或数据路径可独立追踪，探索量明显占用主线程 | `evidence_explorer`，按独立问题拆分实例 | 合并证据、判断真实缺口与未知项，不让探索员直接决定最终方案 |
| 已确认契约下有独立实现单元，文件归属清晰，委派能减少等待或主线程上下文 | `implementer` | 确认接口与依赖、保留公共文件写入责任、核对最终任务差异 |
| 需要故障复现、独立验收或较长的构建/回归/性能检查，目标和允许操作已明确 | `verifier` | 决定验收契约和允许环境，处理失败、环境准备及用户取舍 |
| 实现已稳定，改动复杂或涉及外部契约、权限、持久化、并发等实质风险；或用户明确要求独立审查 | `reviewer` | 提供完整任务范围，判断发现是否成立，安排修复并综合结论 |
| 难以逆转的架构、数据模型、状态或跨模块契约存在实质方案取舍，已有代码或原型可供检验 | `design_challenger` | 决定技术方案，向用户确认产品与兼容承诺，安排必要实验 |

窄范围查证、小改动或便宜的局部自测可由当前 Agent 完成。`implementer` 负责自己的针对性验证，`verifier` 补独立验收或高价值检查，不重复跑一切测试。纯调查可委派只读角色；没有实施授权时不能委派实现或原型写入。

## 交接最少必要信息

委派前给出目标与完成标准、已确认契约及决策、实际仓库与版本、允许的读取来源和操作、可写文件/模块或产物目录、排除项与依赖。引用明确的任务记录和文件位置即可，不复制整段聊天，也不为交接强制建新文档。

- 实现任务明确每个写入者的归属，公共接口、共享配置与迁移等共用文件由一个负责人处理。工作区已有改动先划清归属；不让子 Agent 覆盖他人现场。
- 验证任务明确预期、入口、数据、环境和允许副作用。临时产物与缓存可按授权使用，不能擅自安装、启动长期服务、改测试预期或写共享数据。
- 完整任务审查交接基线 ref/SHA、任务提交、相关暂存/未暂存/未跟踪内容及排除项，沿用 [验证与审查](verification.md) 的覆盖要求。
- 设计质疑给出已查证的现状、约束和实际候选，不把未验证想法当成实现事实。只需实验才能回答的问题交回主 Agent 安排，不制造额外需求。

角色不直接索取新增用户授权，也不自行派生子 Agent。遇到缺口向主 Agent 返回具体阻塞，继续可独立完成的已授权部分。提交、推送、合并、部署、共享数据与宿主配置操作由主 Agent 依据原授权及专项流程处理。

## 并行与证据对应版本

先拆依赖，再安排并行。多个调查可同时读取；多个实现者只写不冲突的范围。契约或共用文件尚不稳定时先收敛，不通过增加写入者加速。同一浏览器 profile、端口、构建目录或测试数据存在争用时，先隔离或顺序运行。

需要隔离时按目标项目规则和已有授权安排分支或 worktree；不默认创建、切换、迁移或清理用户现场。子 Agent 不自行操作 Git 交付。

受影响实现达到可识别的稳定版本后，运行验证和只读审查可以并行。检查期间相关文件继续变化时，返回结果要保留版本混合的限制；不能把旧结论归到新实现。主 Agent 修复后只补受影响的验证和审查，复用仍有效的结果。

## 返回与综合

子 Agent 返回实际范围与版本、事实或改动、关键证据、未覆盖及需要主 Agent 处理的事项。长日志保存在已授权临时目录，仅回传定位所需片段；证据文件不能含秘密。

主 Agent 阅读改动和证据，核对目标、接口、归属及版本，处理相互矛盾的发现。子 Agent 的“完成”只是输入；主 Agent 对最终结论负责。进程退出为 0、mock 通过或审查未发现问题不能代替相应行为验收。

## 能力不可用或受限

先核对当前会话是否真正提供该角色及完成任务的工具，磁盘存在定义不等于已加载。不能通过改角色配置绕过父会话权限，也不能假装调用了未加载角色。角色不可用或分工条件不满足时，由当前 Agent 完成可做部分并说明影响；用户明确要求的独立验证或审查未执行时，保留未完成状态。

Codex 角色继承父会话的沙箱、审批、provider 与 MCP；角色正文中的只读、文件归属及禁止派生是职责约束。OpenCode 子角色使用全局默认与自身规则，不保证继承父角色的所有限制；主 Agent 必须将原任务允许的操作范围交接给子角色。工具规则可限制编辑或常见直接命令，但允许 shell 执行不能证明源码不可被间接写入。实际隔离能力和原生加载情况分别验证，不把配置断言或离线模型样例当成系统隔离证明。
