# 任务记录

记录服务于恢复和追溯，不能替代真实文件、Git、环境和验证状态。

## 何时记录

- 小改动和仅在对话中进行的分析默认在对话汇报；多轮问答或跨仓本身不强制创建任务编号、计划文件或主记录。
- 已有主记录先恢复并维护；用户要求保存，或任务已进入实施且确需跨会话恢复时，按项目规则复用或建立最少必要记录。公司扩展可规定正式交付的建档条件和位置。
- 独立计划不自动升级为已授权交付任务，拟操作不构成实施授权。写入前加载目标目录规则并核对写入范围。

## 保留什么、何时更新

保留目标与来源、确认范围与排除项、处理方案及必要决策、实际验收入口、当前实现与验证版本、结果和下一步。区分待用户决策、待代码或环境核实、已实现但未验证的事项；尚不适用的字段省略，不生成固定文件套件。

已有记录在探索形成稳定结论、用户确认关键口径、方案或实现变化、完成验证与交付动作时增量更新；转入实现或结束本轮前核对一致性。更新原位置的有效结论，不记录搜索和聊天流水，不平行维护多份总进度。长期知识与拟采用方案分别表达，历史交付记录不自动变成现行规范。

证据标明实际版本和未提交范围；跨仓分别记录实现和交付状态。记录中的历史操作和计划不能作为新会话的授权凭证。文档、图示和清单只能反映已知状态，不能证明操作已经执行。
