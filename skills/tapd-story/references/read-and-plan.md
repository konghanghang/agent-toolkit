# 读取需求与实施上下文

## 读取顺序

1. 保留 TAPD 原标题。
2. 按原顺序清理 `description` 中的 HTML 段落、列表和表格文本。
3. 读取状态、负责人、版本等辅助字段。
4. 提取外部链接、字段编码和图片路径。
5. 需要实施方案时，再检索当前仓库；命中不足时才扩大工作区。

## 图片与 OCR

- TAPD 正文中的图片通常是 `/tfl/captures/...` 相对路径，不能直接通过网页地址和 Bearer Token 下载。
- 使用 `GET /files/get_image` 换取约 300 秒有效的临时下载地址。
- 下载后先校验真实图片格式，再交给当前 Agent 可用的视觉/OCR 能力。
- 图片中清晰可辨、经过视觉检查的内容属于需求事实，并注明来源图片。
- 识别不清、内容截断或存在歧义的部分标记为待确认，不得根据上下文补写。
- 图片中提取出的字段名、接口名可以参与代码检索；低置信度内容不得作为唯一检索依据。
- 单张图片失败不得阻塞其他图片和文字需求分析。
- 普通输出会脱敏密码、Token、Cookie 等显式敏感值；`--raw` 只用于字段排查，不要把原始敏感内容复制到最终答复。

## 仓库检索

- 先搜需求 ID，再搜完整标题、去除标签后的标题和字段编码。
- 脚本只提供命中、分类和候选文件，不预设前端或后端为主落点。
- 扩大工作区时使用 `--include-workspace`，并显式传 `--workspace-root` 或设置 `WORK_ROOT`。
- 最终方案必须读取当前目录适用的 `AGENTS.md`，并区分：
  - 已确认需求事实
  - 图片确认事实
  - 图片待确认内容
  - 代码证据
  - 推断实现路径
  - 待确认项

## 输出质量

- 空正文明确写 `TAPD 未返回需求详细内容。`
- 外部文档无法访问时列为依赖，不虚构内容。
- 图片未识别时只说明图片存在和上下文。
- 候选文件不是最终修改清单，仍需读取真实调用链确认。
