# 读取需求与实施上下文

先按 SKILL.md 恢复本地任务；以下是确定需要远端读取后的正文处理顺序，不是收到需求 ID 后的默认起点。

## 读取顺序

1. 保留 TAPD 原标题。
2. 按原顺序清理 `description` 中的 HTML 段落、列表和表格文本。
3. 读取状态、负责人、版本等辅助字段。
4. 提取外部链接、字段编码和图片路径。
5. 列出需求附件；按需通过可重复的 `--attachment-id ID` 选择下载；确需全部时使用 `--download-attachments`，下载到交接目录的 `attachments/`。
6. 需要实施方案时，再检索当前仓库；命中不足时才扩大工作区。

## 图片与 OCR

- TAPD 正文中的图片通常是 `/tfl/captures/...` 相对路径，不能直接通过网页地址和 Bearer Token 下载。
- 使用 `GET /files/get_image` 换取约 300 秒有效的临时下载地址。
- 下载后先校验真实图片格式，再交给当前 Agent 可用的视觉/OCR 能力。
- 图片中清晰可辨、经过视觉检查的内容属于需求事实，并注明来源图片。
- 识别不清、内容截断或存在歧义的部分标记为待确认，不得根据上下文补写。
- 图片中提取出的字段名、接口名可以参与代码检索；低置信度内容不得作为唯一检索依据。
- 单张图片失败不得阻塞其他图片和文字需求分析。
- 普通输出会脱敏密码、Token、Cookie 等显式敏感值；`--raw` 只用于字段排查，不要把原始敏感内容复制到最终答复。

## 附件

- 使用 `GET /attachments` 按需求 ID 分页列出独立附件，再按需使用 `GET /attachments/down` 换取临时下载地址。
- 默认保存到 `Path(tempfile.gettempdir()) / f"tapd-story-{story_id}" / "attachments"`；与图片目录并列，不持久化到业务仓库或知识库。
- TAPD 正文是需求事实。附件是客户原始材料，产品通常已整理进正文；正文足够时不要打开。
- 正文缺失、含糊、明确要求参照附件、已有证据表明内容冲突，或用户要求读取附件时才按需下载和读取。能读的文档只抽取确认事实和待确认项，不要把 Word/Excel/PDF 全文复制进需求正文或最终答复。
- 附件列表或单文件失败不得阻塞文字需求分析。

## 渐进式实施上下文探索

形成方案前先核实已有接口和业务能力，不把需求中的“新增”直接等同于必须新建实现。工作项目的已有能力、调用方兼容和修改范围检查，按 [交付规则第 1 节](../../work-feature-delivery/references/delivery-workflow.md#1-影响分析) 执行，不在本技能重复维护。

1. 先根据用户目标确定本轮需要回答的核心问题和交付内容。
2. 将用户明确指定的仓库、模块、文件或接口作为首轮探索边界；用户未指定代码入口时，再从 TAPD 已确认的业务入口开始定位。
3. 每次扩大探索范围前，先明确当前缺少的事实，以及该事实会改变哪项结论，例如修改落点、外部行为、兼容性判断或交付范围。
4. 无法说明新增探索会改变哪项结论时，不扩大范围。
5. 现有需求事实和代码证据已经能够支撑修改范围、核心方案和必要风险判断时，停止探索；已建档任务将稳定结论、证据版本及未核实边界更新到原记录，不能只留在工具临时报告中。
6. 对当前结论非必要、但可能有价值的信息，记录为后续检查项，不阻塞当前回答。
7. 用户要求完整影响分析、实施计划、发布方案或正式 Code Review 时，根据交付目标提高探索深度。

## 并行与依赖

- 相互独立的事实获取任务可以并行执行；后续任务必须依赖前序结构化结果时，才串行执行。
- 用户已提供明确代码入口时，代码现状读取可以与 TAPD 需求读取并行；最终结论必须在需求事实和代码事实汇合后形成。
- 不为了并行而提前扩大代码探索范围。

## 仓库检索

- 先搜需求 ID，再搜完整标题、去除标签后的标题和字段编码。
- 脚本只提供命中、分类和候选文件，不预设前端或后端为主落点。
- 需要扩大工作区时，使用 `--include-workspace`，并显式传 `--workspace-root` 或设置 `WORK_ROOT`。
- 最终方案必须读取当前目录适用的 `AGENTS.md`，并区分：
  - 已确认需求事实
  - 图片确认事实
  - 图片待确认内容
  - 仅在正文不足时从附件确认的事实
  - 代码证据
  - 推断实现路径
  - 待确认项

## 输出质量

- 空正文明确写 `TAPD 未返回需求详细内容。`
- 外部文档无法访问时列为依赖，不虚构内容。
- 图片未识别时只说明图片存在和上下文。
- 分别说明附件已列出、已下载、已读取的状态；只有已下载才提供本地路径，已读取才报告提取的事实。
- 候选文件不是最终修改清单，仍需读取真实调用链确认。
