# 待处理列表夹具与恢复指南

只在任务涉及待处理列表、连续处理或恢复测试数据时读取。具体页面、接口、表名、状态值和关联字段由目标项目的代码与规则提供，本文件不保存产品数据库或页面的固定映射。

造数和恢复必须走 `$verify-test-db`：先完整展示目标 profile、数据库、记录范围、写入 SQL、回滚 SQL 和预期差异，再等待用户针对该计划明确确认。目标、SQL 或影响范围变化后重新确认。

## 定位真实过滤条件

- 沿页面请求、Controller、查询和 Mapper 核对列表过滤条件，不能只凭状态字段名判断。
- 确认状态、数据来源、租户、创建人、时间区间和权限过滤是否共同参与查询。
- 根据实际 schema 确认主外键、媒体或详情数据关联，不能编造关联 ID。
- 页面有行但详情或媒体为空时，继续追踪请求与关联数据，不把“插入成功”当作夹具可用。

## 准备与恢复

优先复用已存在且关联完整的测试记录，并在操作前保存脱敏快照。只修改已确认会影响测试目标的字段；不把一次人工备注、某次真实客户内容或任意主键写成公共标准数据。

恢复前核对基线、当前值和本次修改范围。恢复状态不等于恢复备注、来源或审计字段；未取得原值的字段不能声称已经还原。

## 页面查询

- 先确认页面当前日期、状态和其他筛选条件，避免将前端筛选误判为数据未入库。
- 页面过滤不匹配时优先调整当前测试窗口的查询条件；修改持久化日期或状态必须另有相应数据写入授权。
- Playwright MCP 窗口中的表单状态与用户自己的浏览器会话分别核对。

## 连续处理断言

先确认项目的交互契约，再选择断言：

- 提交后是保留当前位置、选择下一条还是清空详情。
- 下一条和最后一条处理后，列表、选择项及详情面板是否一致。
- 自动播放是否只在约定的触发方式下发生，播放器起点与目标内容是否对齐。
- 切换记录时按新记录完整填充表单；没有对应值的字段应回到空值或默认值，不能带入上一条备注。
- 手动选择、已处理列表、失败重试等路径是否遵守各自的播放和提交约定。

## 证据与禁止事项

记录本次夹具的脱敏标识、操作前后差异、页面路径和恢复结果。具体手机号、账号、租户 ID、主键、客户备注、凭证及环境 schema 只留在授权的私有测试记录中，不提交到公共 Skill。
