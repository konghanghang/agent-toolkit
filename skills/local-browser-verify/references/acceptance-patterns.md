# 通用页面验收断言

只读取与本次需求有关的小节。这里定义的是可观察结果，不要求项目使用特定框架或 CSS 类名。

## 布局和响应式

至少记录视口宽高、页面根节点的 `clientWidth` / `scrollWidth`、目标容器的边界和 `overflow-x`。分别判断：

- 页面不应横向溢出：根节点 `scrollWidth <= clientWidth`，并确认不是通过裁掉内容实现。
- 指定区域应横向滚动：页面根节点不溢出；目标容器 `scrollWidth > clientWidth`；计算样式允许横向滚动；实际改变 `scrollLeft` 后内容可达。
- 内容应换行或收缩：目标元素右边界不超过内容容器，文字和控件仍可见、可点击。

桌面和窄屏使用同一组业务内容，避免因为测试数据不同得出错误结论。截图只能辅助说明，宽度和滚动值才是主要证据。

## 表格、代码块和 Mermaid

宽表格和宽代码块应由自己的内容容器滚动，不能撑宽文章正文或整页。检查内容容器、滚动容器和实际表格三层尺寸，不要只看表格本身。

Mermaid 还要确认：

- 源码块已经转换成 SVG，而不是只存在 Mermaid 文本。
- SVG 有非零尺寸，参与者、节点或文字没有被裁掉。
- 需要横向滚动时，滚动发生在图表容器而不是整个页面。
- 实际改变容器 `scrollLeft` 后能看到右侧内容。
- 主题相关改动覆盖浅色和深色；布局相关改动覆盖宽屏和窄屏。

## 折叠导航和树形列表

记录加载后的默认展开项、可见子项数量和滚动高度。验证顺序：

1. 首次进入时默认状态符合要求。
2. 展开一个分组后，只出现该分组的子项。
3. 收起后子项不可见且不继续占布局高度。
4. 需求涉及刷新保持时再验证持久化；未要求时不要自行增加这一口径。

## 异步列表和“下一条”

操作前记录列表记录 ID、当前详情 ID和关键请求。操作后等待业务状态或 ID 变化，不用固定 sleep。分别断言：

- 当前操作确实成功。
- 下一条记录 ID 与上一条不同，并且来自预期列表范围。
- 详情、表单和播放器都已经绑定到新的记录 ID。

网络空闲不代表业务异步已经完成；以页面可观察状态、响应结果或后端允许查询的状态为准。

## 表单重填和清空

切换记录前后记录每个关键字段的值、禁用状态和校验状态。至少覆盖：

- 新记录返回的字段被正确回填。
- 新记录没有返回、但用户在上一条改过的字段被清空。
- 表单实例或数据模型已按新记录 ID 重建，不只是界面文字变化。
- 提交按钮、校验信息和脏状态符合当前记录，而不是继承上一条。

## 媒体和自动播放

自动化证据使用媒体元素或播放器状态：资源 ID / URL、`readyState`、`paused`、`currentTime`、播放事件和错误。只有 `currentTime` 在合理等待后前进，才能证明播放实际开始。

浏览器策略拦截、设备无声或结论依赖听感时标记 `MANUAL`。不要把“调用了 play”“按钮变成暂停”或单张截图直接判为已播放。

## 控制台和网络

在操作前后分别收集与目标路径有关的失败请求和控制台错误。报告时区分：

- 阻止本次路径继续的错误：`BLOCKED` 或 `FAIL`。
- 本次操作触发、且与预期行为冲突的错误：`FAIL`。
- 页面进入前已经存在、与本次功能无关的噪声：记录但不错误归因。

不要因为页面最终看起来正常就忽略本次操作产生的 4xx、5xx、未处理异常或资源加载失败。
