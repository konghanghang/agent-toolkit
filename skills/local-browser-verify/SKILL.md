# 本地浏览器验收

用已启动的本地页面做交互验收。不启动新的长期服务，不把调试产物留在仓库里。

线索信息管理待初审列表的造数和恢复，读 [references/clue-unsubmitted-fixture.md](references/clue-unsubmitted-fixture.md)，并走 `$verify-test-db`。

## 边界

- 只负责：探活、登录、按用户路径点页面、收集可复核证据、清理 MCP 落盘。
- 不替代当前项目的 QA / 实现 Skill。
- 不写入账号、密码、Token、Cookie、验证码。
- 不把「听没听到」「截一张图」当成自动播放或动画已通过。
- 用户只要求讨论方案时，不打开浏览器，不登录，不写库。
- Playwright 窗口不是用户本机已打开的浏览器。改的是 MCP 会话，用户自己的页要他自己刷新或清筛选。

## 工作流

1. **探活**
   查当前仓库的启动进程和实际监听端口，再访问。不要默认 `3000`、`5173`、`8888`、`9527`。进程不在或端口对不上时先停。

2. **确认后端**
   看页面实际请求打到哪套 API。网关 503、CORS、首屏 Network Error、白屏进度条，优先当环境/代理问题。开发态能切环境时，先换到通的那套。当前 shell 没有所需环境变量时，先按当前 shell 的标准方式加载用户明确指定的配置，例如 POSIX shell 的 `source` 或 PowerShell 的点调用（dot-source）；不要自行猜测、遍历或读取配置中的客户端密码。

3. **建立会话**
   Playwright 是新浏览器，复用不到用户已经打开的窗口。账号当场问用户，或让用户在 MCP 窗口里自己登。跨会话复用只用本机 gitignore 的 `storageState`。Skill、仓库、提交说明里都不写密码。

4. **进入目标页后再取数**
   列表为空时，先核对页面默认筛选（当天、近三天、状态、租户、必选企业/任务），再判断没数据。
   要看到历史数据时，优先清搜索日期，不要先改库里的业务时间。控件只能选近几天、又必须用控件筛选时，再考虑改 `call_date`，且必须用户明确要求。

5. **按真实用户路径点**
   点、填、提交、切换 tab。连续处理、自动下一条、表单重填是不同断言，不要测了播放就当成表单也对。

6. **取证**
   - 下一条：刷新后的列表 id、当前记录 id。
   - 自动播放：待播放 id、ready id、计算起点、播放器当前时间、是否 `paused`。听感只标 `MANUAL`。
   - 表单：关键字段在切记录前后的值，以及表单实例是否按记录 id 重建。用户改过、下一条 `intentData` 里没有的字段（如备注）必须被清空。

7. **清理落盘**
   验收开始前记录工作区 `.playwright-mcp/` 和仓库根目录截图、HAR、trace 是否已存在。验收结束只删除本次产生的调试产物；验收前已有的内容视为用户状态，不删除，确需清理时先获得用户明确同意。截图写到 `TMP_DIR`。不要为了省事改无关项目的 `.gitignore`，除非用户明确要求。

## 证据口径

| 结论 | 条件 |
|---|---|
| `PASS` | 实际点过路径，状态或控件时间能复核 |
| `FAIL` | 点过，行为和预期不一致 |
| `MANUAL` | 依赖听感、用户本机窗口，或浏览器策略拦住了媒体 |
| `BLOCKED` | 服务没起来、网关不通、没有账号、筛选后仍无可用数据 |

没有登录态时，不得声称已覆盖需登录的页面。没有可用数据时，不得声称已覆盖提交/下一条/播放/表单重填。
