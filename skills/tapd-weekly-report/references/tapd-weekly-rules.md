# TAPD 周报参考

## TAPD API 说明

- 基础地址：`https://api.tapd.cn`
- 接口：`/stories`
- 必填参数：`workspace_id`、`version`、`limit`、`fields`
- 字段：`id,name,owner,status,version`
- 鉴权：`Authorization` 头里放 Bearer Token

脚本从本机工作配置读取成员与工作区 ID，路径、覆盖规则和初始化方式见 [工作环境私有配置](../../../docs/installation.md#工作环境私有配置)。实际名单和工作区 ID 不写入本文件。

以下底层请求示例使用环境变量传入工作区 ID，需要先设置 `TAPD_WORKSPACE_ID`：

```bash
curl -s -H "Authorization: Bearer $TAPD_TOKEN" \
  "https://api.tapd.cn/stories?workspace_id=$TAPD_WORKSPACE_ID&version=2026-0115&limit=100&fields=id,name,owner,status,version"
```

## 版本规则

- 版本格式：`YYYY-MMDD`，年份和月日之间有一个连字符，例如 `2026-0115`
- 发版日：周四
- 下一个版本：当前版本日期 `+7 天`
- 周报统计区间：该版本所在周的周一到周日

## 输出格式

下例中的成员甲、成员乙、成员丙是说明用名称。实际成员标题和数量统计按本机 `members` 数组动态生成，展示顺序也与该数组一致。

```markdown
# 工作周报 (YYYY-MM-DD ~ YYYY-MM-DD)

## 本周概览

- 本周共 X 个需求，人员分布为成员甲 X 个、成员乙 X 个、成员丙 X 个。
- 本周交付重点集中在若干主题能力推进，并说明关键插单项。
- 上周计划 X 项，本周完成 Y 项，顺延 Z 项，计划兑现率约 N%；如有插单，再说明插单数量和影响。

## 下周重点与风险

- 下个版本（YYYY-MMDD）共 X 个需求，人员分布为成员甲 X 个、成员乙 X 个、成员丙 X 个。
- 下周重点将继续围绕若干主题推进，并点出重点客户/项目。
- 顺延风险主要有若干项；若已知原因，直接补充原因和后续动作。

## 本周完成

### 成员甲
- 需求标题和简要描述

### 成员乙
- 需求标题和简要描述

### 成员丙
- 需求标题和简要描述

**本周完成数量统计**：共 X 个需求（成员甲: X，成员乙: X，成员丙: X）

---

## 下周计划

### 成员甲
- 需求标题和简要描述

### 成员乙
- 需求标题和简要描述

### 成员丙
- 需求标题和简要描述

**下周计划数量统计**：共 X 个需求（成员甲: X，成员乙: X，成员丙: X）
```

## 对比规则

- 默认对比对象：同一 `reports/YYYY/MM` 目录下上一周的周报
- 对比关系：
  - 上周 `下周计划`
  - 本周 `本周完成`
  - 本周 `下周计划`
- 标题经规范化后完全一致的项，可直接自动对比
- 如果父任务和子任务明显是同一条交付线，只保留更具体的一项，并把它们视为同一事项跨周对比
- 如果只是标题改名，但显然还是同一个需求，要手工修正摘要，不要污染详细事实区
- `顺延` 的定义：
  - 上周 `下周计划` 中出现
  - 本周 `下周计划` 中仍然出现
- `插单` 的定义：
  - 本周 `本周完成` 中出现
  - 但上周 `下周计划` 中没有出现
- `未说明去向` 的定义：
  - 上周 `下周计划` 中出现
  - 但本周既不在 `本周完成`，也不在 `下周计划`
- 如果用户明确给了延期或取消原因，要把原因写进摘要
- 如果顺延、改名、取消或去向不明事项无法从当前上下文解释清楚，必须先问用户再定稿
- 不要静默省略“消失的计划项”
  - 只有在用户也无法提供原因时，才保留为 `未说明去向`

## 追问模板

以下场景出现时，保存周报前要先追问：

- 上周计划项既没完成，也没顺延到下周
- 顺延项没有已知延期原因
- 标题变化太大，无法确认是不是同一项
- 本周完成项看起来像插单，但也可能只是上周计划改名

推荐提问形式：

```text
我发现上周计划里有几项没有明确去向/原因，请确认后我再写入周报：
- A：已完成、顺延、取消，还是改名为某个需求？原因是什么？
- B：已完成、顺延、取消，还是改名为某个需求？原因是什么？
```

## 摘要清理规则

- 优先保留标题括号里的客户名或项目名
- 如果需要从标题前缀里抽取客户/项目，要去掉通用后缀
  - 例如 `外呼回调`
  - 过滤流程状态词或能力碎片，例如 `进行中`、`客户导入`、`智能任务回调`
- 除非用户明确希望看到技术标签，否则不要把 `IVR` 这类泛技术缩写当成客户/项目输出
