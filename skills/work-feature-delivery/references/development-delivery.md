# 开发七步交付参考

本文是 `work-feature-delivery` 的执行参考，定义工作项目业务功能、Fix、性能优化和重构从编码到“可以测试”的开发交接状态。知识库的 `knowledge/engineering/development-delivery.md` 只维护团队可见的记录契约；需求主记录的实际写法仍按知识库规则和 `templates/requirement.md` 执行。

## 适用范围

- 工作项目业务代码交付使用本参考；纯文档、Skill、工具箱、CI 或本地工具维护按通用 `feature-delivery` 流程裁剪。
- 七步只表示开发交付状态，不授予提交、推送、合并、部署、配置写入或数据库操作权限。
- 用户已确认的授权继续有效；新的行为、范围或外部操作仍按原授权边界处理。

## 开工前的需求冻结

在首个业务代码修改或委派实现前，主 Agent 需要把以下内容收敛到需求主记录：

- 当前有效的需求事实、用户确认口径和已排除范围；正文、评论、图片或代码之间存在冲突时标明来源和最终采用项。
- 改动前后的用户行为、默认值、兼容行为、数据来源和唯一配置／参数来源。
- 真实菜单、接口或任务入口，以及受影响和明确不受影响的仓库、模块、服务和发布范围。
- 主要验收场景、环境前提、证据缺口和下一步。

仍有影响行为、兼容性、范围或验收的未决项时，停在澄清或只读分析，不创建实现分支、不委派编码。接受推荐方案本身不等于获得实施授权。

## 七步检查

| 步骤 | 进入条件 | 完成证据 |
| --- | --- | --- |
| 1. 编码 | 范围、契约、基线、工作区和主记录已核对，实施已获授权 | 实际差异可审阅，调用方和兼容范围已更新 |
| 2. 开发完成 | 代码实现结束 | 按风险完成适用的编译、测试、差异检查和审查；不为机械透传强行增加测试 |
| 3. 交付材料核对与补齐 | 本轮实现或方案已稳定 | 主记录、测试说明、客户材料和发布清单与最终实现一致；过期方案移入历史 |
| 4. 提交与推送 | 用户分别授权相应 Git 动作 | 各仓提交、分支、推送和未纳入改动分别记录；代码与知识库分开说明 |
| 5. 合并 test | 目标 `test` 已同步，合入范围明确 | 合入版本完成必要复验，推送前后远端关系和实际 merge commit 可追溯 |
| 6. 测试环境构建与环境准备 | 依赖、DDL、配置和构建顺序已核对 | 必要流水线到终态，API／镜像／部署触发、实例版本、Ready、权限、数据和配置前提按实际结果记录 |
| 7. 可以测试 | 测试交接材料和环境前提已就绪 | 测试人员能取得对应版本，按文档找到入口、数据和预期结果；核心场景不存在阻塞 |

第 6 步不能只以 CI 成功勾选；第 7 步不能只以代码合入或部署触发勾选。“可以测试”不表示测试已开始、测试通过、生产已发布或客户已验收。

## 方案变化闸门

用户改变数据语义、配置来源、入口范围或发布范围时，先暂停当前实现并在主记录完成一次变更收敛：

1. 写清旧方案和新方案的差异及原因。
2. 标明已完成代码中哪些保留、回滚、重做或不受影响。
3. 重新核对调用方、仓库、测试入口和发布物料。
4. 将被替代的方案移到带有“历史／已撤回”标识的记录，再按新方案继续。

不能让旧方案继续作为当前实现或当前测试预期，也不能只在文末追加相反结论。

## 最小改动与分工

- 先对比旧链路，优先复用现有数据结构、参数、循环、分片和错误处理。
- 每个新增 Helper、缓存、重放流程、参数或测试文件都要对应一个已确认的行为缺口；无法说明缺口时不新增。
- 公共仓库按模块和真实调用方分别核对；兼容编译不自动扩大发布范围。
- 委派实现前先冻结契约和文件所有权；多个 Agent 不修改同一职责边界，审查只读验证当前完整差异。

## 记录与材料收口

主记录只保留当前目标、最终方案、影响范围、进度、验收摘要和剩余事项。详细内容按读者分工：

- `index.md`：当前状态和导航。
- `testing.md`：测试前提、菜单／接口入口、操作、预期和结果。
- 发布批次：DDL、配置、构建顺序、生产执行、冒烟和回退。
- `history.md` 或分析文件：已撤回方案、完整提交、流水线明细和历史失败。

不要把聊天流水、重复轮询、完整工具输出或重复的提交／流水线表追加到主记录。每完成编码、验证、提交、合并、构建或发现阻塞，都更新原记录的实际版本、结果、`nextStep` 和 `blocker`；不维护第二份总体进度。

## 证据边界

分别记录代码事实、配置／SQL、提交／推送、test 合入、CI 构建、部署触发、实例运行态、功能测试和客户验收。前一层证据不能代替后一层：本地编译不代表环境可用，CI 成功不代表 Pod Ready，Pod Ready 不代表业务结果，业务结果不代表客户验收。
