# 交付记录

记录用于追溯和恢复，不能替代当前 Git、环境或验证结果。不强制 flow-state.json、独立 PRD、issues 或 review 双份报告。

## 何时落盘

- 单仓小改动默认在对话汇报。
- 跨仓、分阶段或明确需要跨会话继续时，优先在已有计划文档维护一段交付记录。
- 确需持久化但没有合适计划：跨仓需求使用 work 知识库 `plans/`；单仓沿用目标仓库计划目录。没有目录约定时只确认落点，不自行建立另一套目录。
- 写入前读取目标目录规则，核对本轮授权是否涵盖该仓库写入；计划公开到站点时只记录可公开给团队的内容。原始 TAPD、附件及完整日志留在临时交接目录，不搬入知识库。
- 提测与上线清单继续位于工作区规定的位置，只链接关联计划，不重复完整开发记录。

## 更新时机

范围确认、关键验证完成、提交或交付状态变化时增量更新，不记录每次工具调用。保存当前结果及解释版本变化所必需的信息，不堆积重复日志。需求完成后保留历史交付性质，不将其当成现行业务规范。

## 最小信息

1. 来源与范围：需求链接或用户说明、已确认行为、排除范围、关键验收点及必要待确认项。
2. 每仓实现与验证：真实仓库位置、基线 ref/SHA、功能分支、当前提交、未提交改动范围、验证命令与结果、审查覆盖版本和发现。
3. 实际交付：test 合入与推送、目标批次、release 合入与推送、Pipeline ID/实际 SHA、环境与运行态验收，各自独立记录。

尚不适用的项省略；需要但未执行的项写“未执行”并说明原因。未知写“待核对”，不根据功能分支基线推断批次，不根据 Pipeline 成功推断业务验收成功。计划里的操作历史不是新会话的授权凭证，授权以用户指令及仍有效的会话上下文为准。

## 简短示例

下面内容嵌入现有计划即可，按实际需求裁剪，不原样填满占位项：

```markdown
## 交付记录

- 来源：需求链接；范围：新增查询条件，历史数据回填不在本轮
- 验收：有条件时按条件过滤；不传条件时保持原有查询行为
- 仓库：实际仓库路径；基线：release 分支及 SHA；功能分支：实际分支
- 代码版本：当前 commit；未提交改动：无 / 本轮相关文件范围
- 验证：实际命令、结果及对应代码版本；真实环境验证未执行
- 审查：覆盖基线至当前版本的完整任务差异；结论及未解决项
- test：合入与推送分别记录；目标批次：已确认日期 / 待定
- release、Pipeline、运行态验收：按实际执行结果记录
- 关联材料：提测链接、批次上线清单链接
- 下一步：具体待办或阻塞
```

多仓时将“仓库、版本、验证、交付状态”按仓库分行，关键验收点只写一次。复杂验收可增加“验收点 → 实现位置 → 验证结果”的短表，无需穷举所有文件和测试。
