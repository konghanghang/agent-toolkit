# work 功能与 Fix 交付

按当前任务推进已授权阶段，复用已有技能与项目规则。开发默认做到实现、验证和结果汇报；分析请求只交付分析。提交、推送、合并、部署、数据库执行分别依据明确授权，已有授权不重复确认。

## 开始或继续

1. 从当前对话确定目标、已确认范围及操作授权，不要求用户重述已有信息。仅要求保存独立计划、尚未关联具体交付任务时，按知识库目录规则归档，不自动建立需求记录；明确开展需求分析或已有需求主记录时，继续对应交付阶段。
2. 按 [阶段衔接](references/stages.md) 选择本轮入口和完成条件，按阶段读取 [交付规则](references/delivery-workflow.md) 的相关章节，不复制维护另一套流程。
3. 收到需求 ID 或继续任务时，先按交付规则 §1.1 查找并读取本地主记录，核对相关实现状态，再按需读取 TAPD 和相关知识；检索范围和冲突处理按交付规则 §1。知识目录需要时参照 [work 工作区约定](../tapd-story/references/work-context.md)。继续已有任务时复用仍有效的结论，编码前补齐必要的能力和链路核对，不机械重做探索。
4. 加载目标仓库规则后，核对真实路径、分支、工作区改动、基线和当前提交。恢复交付时再核对所需远端或环境事实；历史计划和旧报告不能证明当前状态。

技能内的交付规则缺失或不可读时，先完成有依据的分析与只读核对；需要其规则才能决定的动作保持待确认，不猜 release、发布批次或合入方式。

## 执行边界

- 连续推进已授权且前置条件满足的工作，不把每个阶段结束都变成确认关卡。
- 有真实业务歧义时使用 `grilling`，按需用 `domain-modeling` 维护稳定术语或必要决策；范围明确时直接实施。
- 调用当前环境可用的专项技能，沿用其真实工具和安全约束；能力缺失时说明影响，不声称已执行对应验证或操作。
- 不默认创建 worktree、amend、自动重试发布或执行 SQL。现有用户改动按仓库规则保护，不为恢复流程而擅自迁移或清理。
- 已有需求的探索与澄清结束前，按 [交付记录](references/delivery-record.md) 保存稳定事实、确认口径及菜单/功能级影响范围，不能仅交付聊天结论或临时报告。
- 小任务在对话汇报；已进入需求交付的任务，按 [交付记录](references/delivery-record.md) 判断是否复用或新建主记录。跨仓、分阶段或需要持久化本身，不将独立计划升级为交付任务。维护主记录前读取知识库 `AGENTS.md` 和 `templates/requirement.md`，按其规范说明处理方案及必要的核心图；本技能只规定更新时机，不另维护内容规范。

## 验证、审查与结束

开发完成、首次合入 test 前读取 [验证与审查](references/verification.md)，按拟合入版本检查完整任务差异和关键验收点；不涉及 test 合入时，在交付开发结果前执行。按风险验证，不强制 TDD、独立审查报告或固定文件套件。

结束时说明本轮完成的范围、对应代码版本、验证与审查结论、实际执行的交付动作及剩余事项。分别报告本地验证、测试环境验证、部署和运行态验收；未执行、失败、阻塞不能当作通过。

到达用户要求的终点即交付结果；缺少下一动作授权时先准备好可审阅结果，再提出具体授权问题。必要验证失败先修复或报告阻塞，只有用户明确接受限制且符合适用规则时才继续相关后续步骤。
