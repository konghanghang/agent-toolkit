# work 功能与 Fix 交付扩展

本入口自动复用 [通用开发流程](../feature-delivery/SKILL.md)，用户无需分别调用两套流程。先读取目标仓库规则和下列阶段补充，再执行对应通用阶段；公司要求只在适用业务场景生效。通用方法只维护在 `feature-delivery`，本技能维护公司差异。

## 加载顺序与阶段补充

1. 确认当前目标、已确认范围和操作授权，读取通用流程；按 [阶段衔接](references/stages.md) 选择当前入口，提前加载该阶段 [交付规则](references/delivery-workflow.md) 的公司前置条件，不等通用阶段完成后补做。
2. **恢复与影响分析**：收到需求 ID 或继续任务，先按交付规则 §1.1 读取本地主记录并核对实现状态，再按需用 `tapd-story` 补远端原文。知识目录需要时读取 [work 工作区约定](../tapd-story/references/work-context.md)。按 §1.2 将菜单/功能级影响范围、验收入口及稳定结论落盘。
3. **澄清与记录**：按 [通用流程](../feature-delivery/SKILL.md) 进入 `grilling` 的交付澄清，并按其授权规则返回原任务，不另设一轮公司澄清；术语及必要决策按需使用 `domain-modeling`；正式需求按 [交付记录](references/delivery-record.md) 维护主记录，探索与澄清完成前及时落盘。写入前读取知识库规则及 `templates/requirement.md`，不另维护模板。
4. **基线与实施准备**：获得实施授权后，按交付规则 §2 完成 release 基线、发布窗口、分支与工作区检查；已有分支先核对，不重复创建。基线与发布批次分别判断。只有用户明确要求时才创建 worktree，并提前告知原因、路径和分支；不迁移或清理用户现场。
5. **验证与审查**：开发交付或首次合入 `test` 前读取 [work 验证补充](references/verification.md)，其中复用通用验证规则；同版本有效结果直接复用。
6. **后续交付**：提交、合并 `test`、提测物料、上线批次、release 合入和构建验收分别按交付规则 §5–9 及已有授权执行。按需使用对应专项技能；不默认 amend、重试发布或执行 SQL。

已授权且前置条件满足的工作连续推进，不在每个阶段重复确认。仅分析时交付分析；已获实施授权的开发任务默认完成实现、验证、审查和汇报。结束时同步主记录中的实际版本、验证、交付动作与剩余事项，分别报告本地验证、测试环境验证、部署和运行态验收。

通用流程或公司规则缺失、不可读时，先完成有依据的分析和只读核对；依赖缺失规则的动作说明阻塞，不猜 release、发布批次或合入方式。安装时须同时提供 `feature-delivery`；完整 `work` profile 已包含通用组，手动筛选 Skills 时也需包含此依赖。
