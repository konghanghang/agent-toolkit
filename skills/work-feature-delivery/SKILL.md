# work 功能与 Fix 交付

按当前任务推进已授权阶段，复用已有技能与项目规则。开发默认做到实现、验证和结果汇报；分析请求只交付分析。提交、推送、合并、部署、数据库执行分别依据明确授权，已有授权不重复确认。

## 开始或继续

1. 从当前对话确定目标、已确认范围及操作授权，不要求用户重述已有信息。
2. 读取目标仓库适用的协作规则及技能内的 [交付规则](references/delivery-workflow.md)。知识目录需要时参照 [work 工作区约定](../tapd-story/references/work-context.md)。按当前阶段读取相关章节，不复制维护另一套分支、提测和上线规范。
3. 核对相关仓库的真实路径、分支、工作区改动、基线和当前提交。恢复交付时再核对所需远端或环境事实；历史计划和旧报告不能证明当前状态。
4. 按 [阶段衔接](references/stages.md) 选择本轮入口和完成条件。可从提交、提测或验收阶段继续，不机械重走全流程。

技能内的交付规则缺失或不可读时，先完成有依据的分析与只读核对；需要其规则才能决定的动作保持待确认，不猜 release、发布批次或合入方式。

## 执行边界

- 连续推进已授权且前置条件满足的工作，不把每个阶段结束都变成确认关卡。
- 有真实业务歧义时使用 `grilling`，按需用 `domain-modeling` 维护稳定术语或必要决策；范围明确时直接实施。
- 调用当前环境可用的专项技能，沿用其真实工具和安全约束；能力缺失时说明影响，不声称已执行对应验证或操作。
- 不默认创建 worktree、amend、自动重试发布或执行 SQL。现有用户改动按仓库规则保护，不为恢复流程而擅自迁移或清理。
- 小任务在对话汇报；跨仓、分阶段或需跨会话恢复时，按 [交付记录](references/delivery-record.md) 复用需求主记录，只在确需持久化时新增文件。维护主记录前读取知识库 `AGENTS.md` 和 `templates/requirement.md`，按其规范说明处理方案及必要的核心图；本技能只规定更新时机，不另维护内容规范。

## 验证、审查与结束

开发结果交付前读取 [验证与审查](references/verification.md)，检查完整任务差异和关键验收点。按风险验证，不强制 TDD、独立审查报告或固定文件套件。

结束时说明本轮完成的范围、对应代码版本、验证与审查结论、实际执行的交付动作及剩余事项。分别报告本地验证、测试环境验证、部署和运行态验收；未执行、失败、阻塞不能当作通过。

到达用户要求的终点即交付结果；缺少下一动作授权时先准备好可审阅结果，再提出具体授权问题。必要验证失败先修复或报告阻塞，只有用户明确接受限制且符合适用规则时才继续相关后续步骤。
