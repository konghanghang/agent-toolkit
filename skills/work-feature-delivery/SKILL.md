# 工作项目业务开发交付扩展

本入口自动复用 [通用开发流程](../feature-delivery/SKILL.md)，用户无需分别调用两套流程。先读取目标仓库规则和下列阶段补充，再执行对应通用阶段；团队交付要求只在适用业务场景生效。通用方法只维护在 `feature-delivery`，本技能维护公司差异。

先按 [五类入口](references/stages.md#按当前材料选择入口) 恢复本轮目标与已有成果，从需要的阶段继续。入口与交付类型分别判断：独立业务功能、性能优化、重构等业务代码交付的 TAPD 与编号规则，以及无 ID 讨论转正式需求的条件，统一见 [交付规则 §1.3](references/delivery-workflow.md#13-入口收敛与正式建需)。纯问答、只读排查、纯专项审查或提交、工具箱及本地工具维护，不强制补 TAPD 或重走开发。

开发阶段从编码到“可以测试”的状态、需求冻结、方案变化闸门和材料收口见 [开发七步交付参考](references/development-delivery.md)。需求主记录的团队可见写法仍按知识库的开发交付进度规范和 `templates/requirement.md` 执行；本技能不另建第二份总体进度。

## 业务实施与收尾必检

- **实施前**：所有准备实施的新业务代码任务，先完成 [§1.3 的边界收敛检查](references/delivery-workflow.md#13-入口收敛与正式建需)，无真实未决项时简短说明已确认，不为形式追加问题或开工确认。获得实施授权后，在首个业务代码修改或委派实现前，必须按 [交付记录](references/delivery-record.md#实施前检查) 恢复并更新已有主记录，或按知识库编号规则和模板建立最小主记录。单仓小改只精简内容，不能免建档；记录或编号阻塞时先做独立只读调查，不先编码再补记录。已有记录及时更新。
- **本轮收尾前**：业务开发任务在开发结束或本轮结束前，更新主记录中的实际方案、影响范围、版本与验证，盘点发布服务、SQL、配置和脚本。按 [交付规则 §8](references/delivery-workflow.md#8-上线清单) 确定批次并增量更新上线清单、建立双向链接；批次确有歧义时在主记录保存物料、原因和下一动作，不伪造批次，也不阻塞已授权且独立的开发。未要求提测、提交或合入 `test` 也必须检查适用材料。
- **结果汇报**：给出实际更新的主记录路径、批次清单路径或批次待定原因，并说明材料缺口；缺必需材料不能声称完整交付。建档或准备清单不扩大实施、提交、推送、合并、部署及数据库执行授权。

## 加载顺序与阶段补充

1. 确认当前目标、已确认范围和操作授权，读取通用流程；按 [阶段衔接](references/stages.md) 选择入口和当前阶段，提前加载该阶段 [交付规则](references/delivery-workflow.md) 的公司前置条件，不把每次给 ID 都当作新需求，也不等通用阶段完成后补做。
2. **恢复与影响分析**：收到需求 ID 或继续任务，先按交付规则 §1.1 读取本地主记录并核对实现状态，再按需用 `tapd-story` 补远端原文。知识目录需要时读取 [工作区约定](../tapd-story/references/work-context.md)。已有或明确要求创建主记录时，按 §1.2 将菜单/功能级影响范围、验收入口及稳定结论落盘。
3. **澄清与记录**：按交付规则 §1.3 交替探索和 `grilling` 的交付澄清，复用已确认口径，只补新增或冲突项；收敛后按原有创建、实施授权继续，不另设“共同理解”或开工确认。需新增 TAPD 的无 ID 讨论先形成草稿，有明确创建授权才用 `tapd-story` 建需并取得真实 ID；认可方案不新增创建或实施授权。术语及必要决策按需使用 `domain-modeling`；正式需求按 [交付记录](references/delivery-record.md) 维护主记录，探索与澄清完成前及时落盘。写入前读取知识库规则及 `templates/requirement.md`，不另维护模板。
4. **基线与实施准备**：获得实施授权后，先完成上述主记录检查，再按交付规则 §2 完成 release 基线、发布窗口、分支与工作区检查；已有分支先核对，不重复创建。基线与发布批次分别判断。只有用户明确要求时才创建 worktree，并提前告知原因、路径和分支；不迁移或清理用户现场。
5. **验证与审查**：开发交付或首次合入 `test` 前读取 [work 验证补充](references/verification.md)，其中复用通用验证规则；同版本有效结果直接复用。
6. **后续交付**：提交、合并 `test`、提测物料、上线批次、release 合入和构建验收分别按交付规则 §5–9 及已有授权执行。按需使用对应专项技能；不默认 amend、重试发布或执行 SQL。

已授权且前置条件满足的工作连续推进，不在每个阶段重复确认。仅分析时交付分析；已获实施授权的开发任务默认完成实现、验证、审查及上述收尾检查后汇报，分别报告本地验证、测试环境验证、部署和运行态验收。

通用流程或公司规则缺失、不可读时，先完成有依据的分析和只读核对；依赖缺失规则的动作说明阻塞，不猜 release、发布批次或合入方式。安装时须同时提供 `feature-delivery`；完整 `work` profile 已包含通用组，手动筛选 Skills 时也需包含此依赖。
